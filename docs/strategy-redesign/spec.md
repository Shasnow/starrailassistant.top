## 2. 背景与目标

现有攻略站是 787 行的单体 Vue 岛、单列卡片、全量列表，缺少搜索、分类、排序、收藏与点赞；详情接口不返回 `id`，导致详情内下载无效；首屏依赖约 240KB JS 执行后才出现内容。

本次改版目标：

1. 用“搜索 + 关键词分类 + 排序 + 收藏”缩短找攻略路径。
2. 建立统一的 token 化视觉系统，兼容 Starlight 明暗主题。
3. 点赞/收藏后端持久化并绑定账号，保留分享码合并、上传、官方转换、我的攻略等既有流程。
4. 全响应式、基础无障碍达标，并保证首屏 <2s。
5. 产出可维护的设计与交互说明，作为实现与验收依据。

```

│  ├─ 视图：全部攻略 / 我的收藏 / 我的攻略（后两者需登录）
│  ├─ 排序：综合推荐 / 最新更新 / 最多点赞 / 最多收藏
```

### 3.1 分类规则（纯前端）

- 只匹配标题 + 描述，不写库、不改后端字段。
- 一份攻略可命中多个分类；卡片最多展示 3 个标签。
- 分类 chip 单选，显示当前视图 + 搜索范围内的计数；计数为 0 时禁用。
- 规则集中在 `categories.ts`，后续只改词表即可迭代：

| --- | --- |
| 量子同频 | `/量子同频|量子/` |
| 列车同行 | `/列车同行|列车/` |
| 奇兽花园 | `/奇兽花园|奇兽/` |

### 3.2 排序与合并

- 综合推荐：点赞 ×2 + 收藏 ×3，同分按更新时间倒序。
- 最新更新：`updateTime` 倒序。
- 最多点赞 / 最多收藏：对应计数倒序，同分按更新时间。
- 分享码先归一化（去空白、去首尾 `#`）再分组；空分享码按攻略 ID 独立成组。
- 分组在分页前完成；组内按当前排序取第一条作为代表，展开后可查看其余版本。

## 6. 交互说明

### 6.1 搜索与筛选

- 搜索 200ms 防抖；空白分词，多个词之间为 AND。
- `/` 聚焦搜索框；Esc 清空搜索（焦点在搜索框时）。
- 分类 chip 单选，`aria-pressed`；点击已选中的 chip 不做切换（保持当前分类），通过“全部”重置。
- 视图切换：全部 / 我的收藏 / 我的攻略；后两者未登录时显示登录引导，不跳转。
- 排序切换即时生效，保持当前搜索与分类。
- 结果数通过 `aria-live="polite"` 播报，例如“共 8 组 / 10 份攻略 · 量子同频”。

### 6.2 卡片与分享码

- 点击标题或“详情”按钮打开详情弹窗。
- 点赞/收藏为可切换按钮，`aria-pressed` + 计数；登录后可用。
- 分享码组卡展示“同分享码 N 份”，展开后显示其余版本（标题/作者/时间/点赞），每条均可详情、下载、删除（本人）。
- 组内成员同样参与搜索/分类；搜索结果只保留命中成员。
- 删除仅“我的攻略”可用，使用确认弹窗；删除后若当前页为空则回退一页。

### 6.3 点赞 / 收藏

- 乐观更新：点击立即翻转状态与计数，请求失败回滚并 toast。
- 未登录：记录待执行动作（sessionStorage），打开登录弹窗；登录或 OAuth 回调成功后自动重放。
- 请求中按钮禁用，防止重复提交；服务端唯一索引兜底。
- API：`PUT/DELETE /strategy/{id}/like`、`PUT/DELETE /strategy/{id}/favorite`；列表返回 `liked/favorited` 标记。

### 6.4 详情与下载

- 详情展示分类、简介、点赞/收藏、最低金币、中期等级、分享码、前台/后台阵容。
- 分享码“复制”按钮写入剪贴板并 toast。
- 下载按 SRA 字段白名单重建 JSON，保持 `tasks/currency_wars/strategies/*.json` 契约不变。
- 详情接口需返回 `id`，修复现有“详情内下载无效”的问题。

### 6.5 上传 / 转换 / 编辑

- 保留现有流程：上传 JSON（拖拽/选择）、一键转换官方攻略、预览编辑、下载/上传。
- 上传后的攻略默认不公开，由 SRA 角色审核发布；页面提示“审核通过后出现在全部攻略”。
- 编辑表单新增分类标签预览（只读，不写库）。

### 6.6 状态与反馈

| 状态 | 表现 |
| --- | --- |
| 加载中 | 6 张骨架卡；列表容器 `aria-busy="true"` |
| 空收藏 | 说明 + “去全部攻略看看” |
| 空上传 | 说明 + “上传攻略” |
| 无匹配 | 说明 + “清除筛选” |
| 加载失败 | 说明 + “重新加载” |
| 操作成功/失败 | 底部 toast；成功绿、失败红；3 秒自动消失 |

## 9. 性能预算

- 首屏目标：Fast 4G / 4× CPU 下 <2s；策略区在 JS 执行前已有静态骨架，避免空白。
- 不新增 web font、装饰图片或大型依赖；视觉装饰使用 CSS/内联 SVG。
- 列表只渲染当前分页组（≤24 组），避免长 DOM。
- 实测构建体积（2026-11-20）：`StrategyApp` JS 55.5KB（gzip 18.0KB），页面 CSS 26.3KB（gzip 5.7KB）。
- 预算：页面自有 JS gzip ≤25KB、CSS gzip ≤10KB；当前均达标。
- 验证方式：`pnpm build` 记录 chunk 体积；`pnpm preview` 记录 `DOMContentLoaded`、LCP 与策略 chunk 耗时；仓库无 Lighthouse/Playwright，使用浏览器 Performance 面板留档。

## 10. 验收标准

1. 1440/834/390 三档均无横向滚动，卡片分别 3/2/1 列。
2. 搜索、分类、排序、视图切换、分享码展开、详情、点赞、收藏全部可用。
3. 登录前点击点赞/收藏会进入登录引导，登录后自动重放。
4. 加载、空、错误、无匹配四种状态均有明确出口。
5. 键盘可完成搜索、筛选、打开/关闭详情、点赞/收藏；焦点可见。
6. 明暗主题下正文与次要文字对比度达标；减少动效设置生效。
7. 首屏骨架先于 JS 出现，构建体积在预算内。
8. 详情下载生成与 `tasks/currency_wars/strategies/template.json` 一致字段的 JSON。
9. 管理后台 `/strategy/all`、`publish`、`delete` 行为不变。

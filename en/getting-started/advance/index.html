Advanced Usage

This page introduces SRA’s more advanced features so you can get the most out of it.

Multi-Account Management

Section titled “Multi-Account Management”

SRA lets you configure a separate automation profile for each account. The following instructions use the operation panel from version 2.0.0 and later as an example.

Create a New Profile

Section titled “Create a New Profile”

Click the + button on the left of the operation panel to open the profile name input box. Enter a profile name and click the confirm button on the right to add a new profile to the configuration list. If the profile name is empty, the input box closes and nothing happens.

Example

Section titled “Example”

Each configuration profile corresponds to the automation setup for one account. Suppose you want to configure accounts A, B, and C.

  • For account A Use the default profile Default and finish the task configuration on the Task tab. When using multi-account management: These tasks must be configured:
    • Click Start Game - select Game Path
    • Click Start Game - check Auto login (fill in the account and password at the same time)
    • Click In the End - check Log out of the current account These tasks must not be configured:
    • Exit the game
    • Exit SRA
    • Shut down
    • Sleep After finishing the task configuration, the following actions save the current configuration profile:
    • Switching profiles
    • Running tasks
    • Closing the window
  • For account B Click the + button on the left of the operation panel, enter a profile name such as ‘planB’, and click the confirm button. Open the configuration profile selector on the right to see the new planB profile. Select it, then configure planB the same way as the Default profile.
  • For account C Same as above.

Now we have three profiles: Default, planB, and planC. All that’s left is to switch the button on the operation panel to Launch All mode and click it to start multi-account management. Profiles run from top to bottom: Default, then planB, then planC. For multi-account management to work as expected, we recommend checking Always log in again for each profile and filling in the account and password, so SRA logs in to the right account automatically when launching the game. You can now return to the SRA operation panel and click Launch All to start your multi-account automation.

Custom Currency Wars Strategies

Section titled “Custom Currency Wars Strategies”

The Currency Wars task in SRA uses predefined strategies. See tasks/currency_wars/strategies/template.json.

Writing a Strategy

Section titled “Writing a Strategy”

You can follow the fields in this file to customize your own strategy. See Creating and Adding Custom Currency Wars Strategies for details.

Downloading Strategies

Section titled “Downloading Strategies”

If you don’t want to write strategies yourself, you can download strategies made for SRA from the SRA strategy site.

Adding a Strategy

Section titled “Adding a Strategy”

Open the tasks/currency_wars/strategies/ folder and put the strategy file you wrote or downloaded (for example my_strategy.json) into it. In the Currency Wars task configuration in SRA, click the refresh button to the right of the Strategy drop-down menu, and your strategy will appear in the list. Select it to use your custom strategy.

Extensions

Section titled “Extensions”

Click Extension in the sidebar to open the extension tab.

Auto Dialogue

Section titled “Auto Dialogue”

When enabled, dialogue plays automatically and dialogue options are selected automatically when a story sequence starts. Skip dialogue: requires Auto Dialogue to be enabled first; once enabled, skippable dialogue is skipped automatically when a story sequence starts. Extensions take effect immediately after being enabled and keep running until you uncheck them.

Settings

Section titled “Settings”

Click Setting in the sidebar to open the tab where you can change SRA’s settings.

General Task Settings

Section titled “General Task Settings”

  • Game Path: sets the game’s installation path. By default, SRA detects the game paths of all installed clients on this device and lets you choose one. Turn off auto-detection to add a game path manually.
  • Use Star Rail Cloud Game (experimental): when enabled, SRA automates the game through Star Rail Cloud. Expand it to configure:
    • Browser: Microsoft Edge, Chrome for Testing, or Firefox; defaults to Microsoft Edge.
    • Browser executable path: leave empty to use the installed browser; set it when you need a specific build.
    • Browser headless mode: runs the browser in the background without a window; required for Docker deployments.
    • Mute browser audio: mutes the browser while running the cloud game.
    • Combined with “QR code login (cloud game)” in the Start Game task, you can log in by scanning without entering an account or password.
    • Cloud game login state is stored per configuration name, encrypted, in cache/cloudgame/<configuration>.json, so switching accounts does not require logging in again.
  • Image recognition confidence threshold: controls how strict the app is when recognizing in-game elements. The default is 0.90 (90%) and can be adjusted between 0 and 1 in steps of 0.01. Higher values make recognition stricter (fewer false positives); lower values widen the range (false positives may occur).
  • Stop hotkey: sets a global hotkey that immediately stops the current task while it is running. The default is F9. Click the input box and press the hotkey you want to change it. Click elsewhere to cancel the change.

Game Launch Arguments

Section titled “Game Launch Arguments”

  • Enable window settings: when enabled, SRA applies the settings below when launching the game.
  • Window Size: sets the game window resolution. The default is 1920x1080 and cannot be changed; only this resolution is supported.
  • Display Mode: sets the game’s display mode. The default is Windowed, and it can be switched to Fullscreen.
  • Borderless Window: when enabled, the game window has no border or title bar, for a more immersive experience.
  • Advanced Parameters: extra game launch arguments can be added in this input box.
  • Launch Game Using CMD: when enabled, SRA launches the game through the command line (CMD), which can be more effective for some games that need specific environment variables or arguments.
  • In addition, enabling launch arguments also turns on the following:
    • Follow auto-battle settings and enable auto battle

In-Game Hotkey Settings

Section titled “In-Game Hotkey Settings”

If you change hotkeys in the game, update the hotkeys here accordingly so SRA can perform in-game actions correctly.

Display Settings

Section titled “Display Settings”

  • Background Image: sets the background image of the home page. Paste the local path of an image into the input box to change it; common image formats such as PNG and JPG are supported. For example, "C:\path\to\your\image.png". If the input box is empty, the default background image is used.
  • Background Image Opacity: adjusts the opacity of the home page background image. The default is 0.9 (90% opaque). Drag the slider to fine-tune between 0 and 1; lower values are more transparent, higher values are clearer (0 is fully transparent, 1 is fully opaque).
  • Control Panel Opacity: adjusts the opacity of the control panel background. The default is 0.9 (90% opaque). Drag the slider to fine-tune between 0 and 1; lower values are more transparent, higher values are clearer (0 is fully transparent, 1 is fully opaque).
  • Language: selects the display language of the app interface. The default is “简体中文” (Simplified Chinese). It can be switched to “English”; the app must be restarted for the change to take effect.

General Settings

Section titled “General Settings”

  • Notification management
    • Allow Notification: the master switch. Notifications of all kinds can only be received after it is enabled (enabled by default); when it is off, all notifications are blocked.
    • System Notification: when enabled, the app sends reminders through system pop-ups (such as update notices and task completion prompts; enabled by default).
    • Email Notification: when enabled, the app sends important information by email (such as error alerts; disabled by default). The receiving mailbox must be configured in advance.
      • SMTP Settings: see the Notification Configuration → Email Notification section below.
    • External notification channels: supports channels such as Webhook, Telegram, ServerChan, OneBot, Bark, Feishu, WeCom, DingTalk, Discord, and xxtui. See the Notification Configuration section below.
  • Create desktop shortcut: if you previously chose “Don’t ask again” in the dialog that offers to create a desktop shortcut, you can create the shortcut again here.

Update Settings

Section titled “Update Settings”

  • Check for updates: click the button to check for a new version manually.
  • Auto Update: when enabled, the app detects new versions automatically and downloads and extracts the update package.
  • Mirror Chyan CDK: enter the authorization code (CDK) for the Mirror Chyan accelerated download service to unlock accelerated update downloads. Input is masked with “*”, and the CDK status (such as “Activated” or “Expired”) is shown below.
  • Update Channel: selects the download source for update packages. The default is “GitHub” (official source, no authorization required). It can be switched to “Mirror Chyan” (accelerated source, requires a valid CDK) or AUTO-MAS (mirror source provided by AUTO-MAS, no authorization required).
  • Application Channel: selects the app’s version type. The default is “stable” (stable release with fewer bugs, suitable for daily use); it can be switched to “beta” (test release with the newest features and possibly a few bugs).

Advanced Settings

Section titled “Advanced Settings”

  • Folder shortcut buttons: click the corresponding button to quickly open the related folder of the app:
    • Backend log folder: the folder that stores the app’s frontend runtime logs.
    • Frontend log folder: the folder that stores the app’s backend runtime logs.
    • Configuration folder: the folder that stores user configuration files (such as task configurations and multi-account configurations).
    • Application folder: the folder that stores temporary data and cache generated while the app runs.
  • Resources integrity check / Resources cleanup: see Resources Integrity Check and Cleanup below.

Resources Integrity Check and Cleanup

Section titled “Resources Integrity Check and Cleanup”

Both features rely on the MD5 manifest manifest.md5.json bundled with the installer (in the application root). Only complete builds installed via the installer or the in-app updater contain this file; when running from source or using a distribution without the manifest, SRA reports that the manifest is missing and the features are unavailable.

Resources Integrity Check

Section titled “Resources Integrity Check”

Click Check to the right of “Resources integrity check” and SRA verifies every file in the app directory against manifest.md5.json:

  • Pass: a toast reports “Integrity check passed, N files verified”.
  • Fail: a dialog lists missing files and files that failed verification (MD5 mismatch, possibly corrupted or from a different version), up to 50 entries per group, with the rest summarized.

The check only reads files and never modifies or deletes anything. If files are missing or fail verification, reinstall via the in-app updater and check again.

Resources Cleanup

Section titled “Resources Cleanup”

Click Clean Up to the right of “Resources cleanup” and SRA scans every file in the application root that is not listed in manifest.md5.json (for example leftovers from older versions, log/, and reports/), then lists their relative paths and sizes in a dialog:

  1. All entries are selected by default; clear individual items or use Select all at the top.
  2. Click Delete selected to delete them; directories that become empty are removed as well.
  3. Files that cannot be deleted because they are in use are reported in the result.

Cleanup decides redundancy only by the MD5 manifest, and the scan covers the whole application directory, so results may include personal data such as logs and reports. Deletion is irreversible; review the list before proceeding. User configurations and cache live in %APPDATA%/SRA (or ~/.config/SRA on Linux) and are out of scope.

Tip

The in-app updater overwrites files incrementally by MD5 and does not delete files removed in the new version. If the installation grows noticeably after updates, use Resources cleanup to reclaim those leftovers.

Multimodal LLM Vision

Section titled “Multimodal LLM Vision”

In some scenarios SRA prefers a multimodal LLM to locate UI elements for higher recognition accuracy (for example, locating the event frame at event-type stops in Divergent Universe). The feature is off by default; when disabled, SRA uses local recognition only.

  • Enable multimodal vision positioning: master switch.
  • Endpoint: must be compatible with the OpenAI chat/completions protocol.
  • Model ID: the multimodal model to use, for example gpt-4o-mini.
  • API Key: the key used to call the endpoint, stored encrypted.
  • Request timeout (seconds): timeout for a single request, 30 seconds by default.
  • Proxy address: proxy used when calling the model; leave empty for no proxy.

Caution

When enabled, requests are sent to the model provider and incur a fee. The exact cost depends on the provider’s pricing.

Developer Options

Section titled “Developer Options”

Click the version number quickly several times in “About” to reveal Developer Options; turning off “Enable developer options” hides the entry again.

  • Enable developer options: master switch.
  • Save OCR images: when enabled, the app saves the images captured during OCR while running tasks, for analysis and debugging.
  • Show debug info in overlay: draws debug information on the in-game overlay; enable “Enable overlay” in Task Settings first, otherwise nothing is shown.
  • Enable custom backend: when enabled, SRA starts the backend with your own command instead of the bundled backend. The following fields appear:
    • Command / executable: for example python, sra-cli, uv, or an executable path; quoted paths are supported. Leave empty to use python from PATH.
    • Arguments: for example main.py or -m SRACore; when both command and arguments are empty, main.py is used.
    • Working directory: the working directory of the backend process; leave empty to use SRA’s current directory.

Note

“Enable custom backend” is only available in Developer Options. If a remote backend is enabled in Advanced Settings at the same time, the remote backend takes precedence.

About

Section titled “About”

  • Version: shows the current app version. Click the version number quickly several times to enable Developer Options.

Console

Section titled “Console”

The Console tab shows the app’s runtime logs, helping you understand its running state and debug information.

Log Filters

Section titled “Log Filters”

Go to the Console tab to see the log filters. There are five log level buttons:

  • TRACE: trace level, shows the most detailed log information, usually for debugging
  • DEBUG: debug level, shows debug information to help developers diagnose problems
  • INFO: info level, shows general information, usually recording normal program operation
  • WARNING: warning level, shows warnings about potential problems
  • ERROR: error level, shows error messages, usually recording errors during program execution

Click a button to toggle whether logs of that level are shown. A highlighted button means logs at that level are displayed; a dimmed button means they are hidden. If you want to use this information to report a problem to the developers, you must enable the TRACE and DEBUG log levels.

Interactive Input Box

Section titled “Interactive Input Box”

At the bottom of the Console tab there is an interactive input box with the placeholder “Please enter text”, which accepts user input. Type text here and press Enter to submit it. After submission, the text is sent to SRA’s standard input stream for the program to read and process. See Basic Usage of SRA-cli for details.

Restart Button

Section titled “Restart Button”

To the right of the Console text is a restart button (with a rotating arrow icon). Click it to restart the backend service.

Stop Button

Section titled “Stop Button”

To the right of the Console text is a stop button (with a stop icon). Click it to stop the backend service. This is useful when the backend service is running and cannot be stopped normally after entering the run or single command.

SRA Launch Arguments

Section titled “SRA Launch Arguments”

SRA supports command-line arguments that control how the app starts. Here are some common ones:

  • --use-python: enables running the backend from Python source, equivalent to turning on that option in Developer Options.

SRA also accepts arbitrary arguments to pass to the backend program. These arguments are forwarded directly to SRA-cli, letting you specify backend behavior at startup. See SRA-cli Command-Line Arguments for details.

Command Palette

Section titled “Command Palette”

Press Ctrl+Shift+P on any page of the app to open the command palette; press it again or press Esc to close it. The command palette gathers common actions into one searchable list, so you no longer have to look for buttons page by page.

Basic Operations

Section titled “Basic Operations”
  • The input box is focused automatically; type a keyword to filter
  • You can search by command name or command ID, for example “Toggle” or view.toggleTheme
  • ↑ / ↓ move the selection, Enter runs it; you can also click an entry with the mouse
  • Clicking the overlay outside the panel closes it

Notification Configuration

Section titled “Notification Configuration”

SRA supports multiple notification channels that push messages to you when tasks complete, fail, or error out. All channels are off by default; enable and configure the ones you need.

Tip

All notification channels are controlled by the “Allow Notification” master switch. Make sure the master switch is enabled.

Notification Payload Format

Section titled “Notification Payload Format”

When SRA sends notifications to each channel, the payload has the following format (shown for Webhook; other channels format it as plain text):

Field Description
title Notification title
event Name of the event that triggered the notification, same as title
result Result: success for success, fail for failure
timestamp Time the notification was triggered, in YYYY-MM-DD HH:MM:SS
message Notification body

Notification Triggers

Section titled “Notification Triggers”
Trigger result
All tasks completed normally success
A single task failed (returned False) fail
A single task crashed with an exception fail

Email Notification

Section titled “Email Notification”

Email notifications were introduced in version 0.8.1.

In Settings, check Email Notification, then configure the SMTP service below and click verify.

SMTP is a reliable and effective email transport protocol; SRA pushes email notifications over SMTP-SSL.

SMTP Server Address
Section titled “SMTP Server Address”

Choose the correct SMTP server address for the email service provider of the sending mailbox.

Email service provider SMTP server address
QQ Mail smtp.qq.com
163 Mail smtp.163.com
Gmail smtp.gmail.com
Outlook/Hotmail smtp-mail.outlook.com
Yahoo Mail smtp.mail.yahoo.com

The table above lists some email providers and their SMTP server addresses. If your provider is not listed, look it up yourself or ask the provider.

Authorization Code

Section titled “Authorization Code”

An authorization code is a special password that replaces your mailbox password when signing in from a third-party client. You need to enter the authorization code of the sending mailbox.

The steps to obtain an authorization code for some providers are listed below:

  • QQ Mail

    • Sign in to your mailbox, then open the QQ Mail Account and Security Center
    • Under Account and Security -> Security Settings -> SMTP/IMAP Service, enable the service and get the authorization code

  • 163 Mail

    • Sign in to your mailbox, then go to Settings -> POP3/SMTP/IMAP, find IMAP/SMTP Service and click to enable it
    • Follow the prompts in the dialog; the dialog generates an authorization password, which is the authorization code.

  • Gmail

    • Sign in to your mailbox, then open Security -> How you sign in to Google -> 2-Step Verification and follow the instructions to turn on 2-Step Verification.
    • Open App passwords and follow the prompts to get an app password; that password is the authorization code.

Tip

Starting January 2025, the “Enable IMAP” and “Disable IMAP” options are no longer available. IMAP access in Gmail is always on, and your current connections to other email clients are unaffected. You don’t need to take any action.

  • Outlook/Hotmail

    • Sign in to your Microsoft account, then open Additional security options -> Two-step verification and follow the instructions to turn it on.
    • After turning on two-step verification, scroll down to App passwords and click Create a new app password

  • Yahoo Mail

    • Sign in to Yahoo Account Security
    • Click Generate app password or Generate and manage app passwords -> Get Started -> enter your app name in the text field
    • Click Generate password; this password is the authorization code.

For your information security, do not share the authorization code with others, and change it regularly.

Some mailboxes show the authorization code only once, so save it promptly; some providers’ authorization codes expire, so change them before they expire.

SRA encrypts locally stored authorization codes with Windows DPAPI. This encryption uses the current user’s login credentials as part of the key, which means the data can only be decrypted by the same user on the same computer. If you need to migrate configuration files across devices, enter the authorization code again.

The SMTP email push service allows the sending mailbox and the receiving mailbox to be the same. If you don’t have an extra email address, you can fill in the same address for both.

Webhook

Section titled “Webhook”

In Settings, check Enable Webhook and fill in the Webhook URL.

  • Webhook URL: the HTTP endpoint that receives notifications. SRA sends a POST request with Content-Type: application/json, and the request body is the notification payload format shown above.

Tip

Webhook is suitable for integrating with self-hosted services or third-party platforms and is the most flexible channel.

Telegram

Section titled “Telegram”

In Settings, check Enable Telegram notification and fill in the following:

  • Bot Token: the token of your Telegram bot, obtained after creating a bot through @BotFather.
  • Chat ID: the ID of the chat that receives messages, obtainable through @userinfobot.
  • Proxy: if you cannot access the Telegram API directly, enable the proxy and fill in the proxy address (such as http://127.0.0.1:7890).
  • Custom API address: if you use a self-hosted Telegram Bot API server, fill it in here; leave empty to use the official API.
  • Send screenshot: when enabled, notifications include a screenshot of the current game screen.

ServerChan

Section titled “ServerChan”

ServerChan is a service that pushes messages to WeChat.

In Settings, check Enable ServerChan notification and fill in:

  • SendKey: obtained after signing in to the ServerChan website; both the SCT format (SCT...) and the sctp format (sctp...) are supported.

OneBot

Section titled “OneBot”

OneBot is a unified chatbot interface standard, commonly used for QQ bots (such as NapCat, LLOneBot, and others).

In Settings, check Enable OneBot notification and fill in the following:

  • Endpoint: the OneBot HTTP API address (such as http://127.0.0.1:3000).
  • User ID: the QQ number that receives private messages (fill in at least one of user ID and group number).
  • Group number: the group number that receives group messages (fill in at least one of user ID and group number).
  • Access Token: the access token for the HTTP API; leave empty for no authentication.
  • Send screenshot: when enabled, notifications include a screenshot of the current game screen.

Using NapCat as an Example

Section titled “Using NapCat as an Example”

NapCat is one of the actively maintained and easy-to-install OneBot v11 implementations.

  1. Follow the official NapCat documentation to install it and sign in to a QQ account
  2. In the NapCat web console → Network Config → add an HTTP Server
  3. Note the port number (default 3000); the Access Token is optional
  4. In SRA, fill in:
  • Endpoint: http://127.0.0.1:3000
  • User ID: your own QQ number (the bot account sends you a private message)
  • Access Token: the same as the one set in NapCat; leave empty if none is set

Tip

We recommend deploying the bot locally: just set the Endpoint to http://127.0.0.1:<port>, no public network is needed. The bot account and the receiving account can be the same QQ number (sending messages to yourself).

Bark

Section titled “Bark”

Bark is an iOS push notification app.

In Settings, check Enable Bark notification and fill in the following:

  • Device Key: copied from the Bark app home page; separate multiple devices with English commas.
  • Bark API endpoint: the Bark server address, defaults to https://api.day.app; change it when using a self-hosted server.
  • Push level: active (default), timeSensitive (time-sensitive, shown even in Focus mode), or passive (silent).
  • Notification sound: a custom notification sound such as minuet; leave empty for the default.
  • Notification icon: the URL of a custom notification icon (requires iOS 15 or later).
  • Notification group: the group name of the notification in the Bark app, defaults to StarRailAssistant.
  • Encryption key: fill in when end-to-end encryption is enabled; leave empty for no encryption.

Feishu

Section titled “Feishu”

In Settings, check Enable Feishu notification. Two methods are supported:

Option 1: Group bot Webhook (recommended)

  • Feishu notification URL: obtained after adding a custom bot in the Feishu group settings → Group Bots.

Option 2: App API (can send to specific users)

  • Feishu AppId: obtained after creating a custom app on the Feishu Open Platform.
  • Feishu AppSecret: the app secret that goes with the AppId.
  • Receiver ID: the ID of the user or chat that receives messages.
  • ID type: the type of the receiver ID; open_id (default), user_id, or chat_id.

Tip

If both methods are filled in, the App API method takes priority.

WeCom

Section titled “WeCom”

In Settings, check Enable WeCom notification and fill in:

  • Webhook URL: obtained after adding a group bot in the WeCom group settings.
  • Send screenshot: when enabled, notifications include a screenshot of the current game screen.

DingTalk

Section titled “DingTalk”

In Settings, check Enable DingTalk notification and fill in:

  • Webhook URL: obtained after adding a custom bot in the DingTalk group settings → Smart Group Assistant.
  • Signing secret: if the bot has signature verification enabled, fill in the secret starting with SEC; leave empty for no signature.

When creating a DingTalk bot, under security settings select only “Sign”. Do not enable other options (such as custom keywords or IP ranges) at the same time, or notifications will fail to send.

Discord

Section titled “Discord”

In Settings, check Enable Discord notification and fill in:

  • Webhook URL: create and copy the URL in the Discord channel settings → Integrations → Webhooks.
  • Send screenshot: when enabled, notifications include a screenshot of the current game screen.

xxtui

Section titled “xxtui”

xxtui is an aggregated push platform that forwards messages to WeChat Official Accounts, WeCom, DingTalk, Bark, and other channels.

In Settings, check Enable xxtui notification and fill in:

  • API key: obtained from the console after signing in to xxtui.com.
  • Notification source: a message source identifier, optional, such as StarRailAssistant.
  • Notification channel: the target channel, optional, such as WX_MP (WeChat Official Account); leave empty to use the default channel.

Tip

Channels that support sending screenshots (Telegram, OneBot, WeCom, Discord) each have their own “Send screenshot” switch on the settings page.

  • Task notifications: when a task completes or fails and the switch is on, a screenshot of the current game screen is sent along with the notification.
  • Test notification: when you click the Check button to test and the switch is on, the SRA icon is sent instead of a screenshot, so that unrelated content is not captured.
